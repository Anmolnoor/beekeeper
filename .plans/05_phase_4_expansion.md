# Phase 4: Expansion

Phase 4 broadens the product only after the single-agent core and first product layers have proven themselves.

The implementation-ready companion for this phase lives in [`05a_phase_4_build_spec.md`](./05a_phase_4_build_spec.md).

## Goal

- Add optional multi-agent orchestration on top of the proven single-agent core.
- Add desktop and richer web surfaces.
- Add more workers, plugins, and optional memory/retrieval layers.

## Deliverables

- Optional orchestration beyond the single-agent baseline.
- Additional operator surfaces for desktop and richer web usage.
- A broader worker and plugin ecosystem that builds on the stable runtime.
- Optional memory and retrieval capabilities introduced only where they add real value.

## Dependencies

- Requires the single-agent core to remain the canonical runtime path.
- Depends on product layers from Phase 3 being stable before multiplying surfaces and execution patterns.

## Exit Criteria

- Expansion features sit on top of a proven core instead of redefining it.
- Multi-agent, richer surfaces, and optional memory/retrieval remain additive rather than required for the base product.
